Resumos, dashboard e newsletter do Agendão Curitiba (https://agendaocuritiba.github.io/). Responda em português. Esta tarefa roda a cada 2 horas, das 7h às 23h, e faz o trabalho uma vez por dia. A coleta, a deduplicação e a publicação do site rodam sozinhas no GitHub Actions às 6h17 (workflow "Coleta diária", scripts/daily.sh), sem IA. Aqui você só faz o que precisa de IA: escrever o resumo e o preço curto dos eventos novos. Depois republica o site, atualiza o dashboard https://claude.ai/artifact/VC7u1GsWLVdSCTyoz7KwxF e, às sextas, manda a newsletter.

PASSO 1 — Data e repositório: HOJE = `TZ=America/Sao_Paulo date +%F`. No clone do repositório agendaocuritiba/agendaocuritiba.github.io: `git fetch origin main && git checkout -B main origin/main`.

PASSO 2 — Já feito hoje? Se state/resumos.json existir e o campo "run" for igual a HOJE, PARE em silêncio.

PASSO 3 — A coleta de hoje rodou? Leia state/runs.json; o primeiro item é a coleta mais recente. Se o campo "run" não for HOJE: antes das 11h, PARE em silêncio (o GitHub às vezes atrasa o horário agendado). A partir das 11h, avise uma vez no tópico que a coleta do GitHub Actions não rodou hoje (link: https://github.com/agendaocuritiba/agendaocuritiba.github.io/actions/workflows/coleta.yml) e PARE; não avise de novo no mesmo dia (grave {"run": HOJE, "aviso": "sem coleta"} em state/resumos.json, faça commit e push só desse arquivo).

PASSO 4 — Resumos e preços: leia state/pending.json (lista de eventos novos sem resumo, com o texto e os preços que o script tirou das páginas originais em pages[].description e pages[].price). Não abra os sites: use só esse arquivo. Para cada evento, escreva em state/summaries.json ({id: texto}) uma frase em português, com no máximo 170 caracteres, com suas próprias palavras, dizendo o que é o evento e quem se apresenta (sem data, sem preço, sem exageros, sem copiar o anúncio). Se o texto das páginas não bastar, escreva a frase só com o título, a categoria e o local, sem inventar nada. Em state/prices.json ({id: texto}) escreva o preço curto, como "R$ 40 a R$ 120", "A partir de R$ 30" ou "Gratuito"; se o preço não estiver claro, não crie a entrada. Não altere entradas que já existem. Grave os dois arquivos com JSON ensure_ascii=False, indent=1. Depois esvazie a lista: state/pending.json = [].

PASSO 5 — Site: `python3 scripts/build_site.py state HOJE docs 2026-10-17` (lê state/events.json, state/summaries.json e state/prices.json). Grave state/resumos.json = {"run": HOJE, "resumos": <quantos escreveu>, "precos": <quantos escreveu>}. `git add docs state`, commit "Resumos de DD/MM/AAAA: X eventos novos" e `git push origin HEAD:main` (se falhar por rede, tente de novo até 4 vezes, esperando 2, 4, 8 e 16 s; se for recusado porque main andou, faça `git pull --rebase origin main` e tente de novo). Nunca force o push.

PASSO 6 — Dashboard (não mexa em files/index.html): (a) ArtifactData "get" (url do dashboard) de datasets/events, datasets/runs, site/summaries e site/prices; anote as versões e os blobs antigos (source.url = /_blob/<id>). (b) Artifact publish, url do dashboard, asset:true, file_path state/events.json → novo blob; o mesmo com state/runs.json. (c) ArtifactData "batch" com quatro "update" pinados com if_version: datasets/events e datasets/runs com source {kind:"file", url:"/_blob/<novo id>", name} e updated {at:<ISO agora>, by:"Claude"}; site/summaries e site/prices com items = conteúdo de state/summaries.json e state/prices.json (use file_path) e updated = HOJE. (d) Apague os dois blobs antigos (Artifact action "delete", path = id antigo). Nunca apague o dedupe.txt nem o newsletter_py.txt. Se o dashboard falhar, siga em frente e diga no aviso.

PASSO 7 — Newsletter: SÓ se hoje for SEXTA-FEIRA em America/Sao_Paulo. `mkdir -p work/out && cp state/events.json work/out/ && python3 -c "import json;json.dump(json.load(open('state/runs.json'))[0],open('work/out/stats.json','w'))" && python3 scripts/newsletter.py work/out HOJE`. Carregue a ferramenta do Gmail com ToolSearch "select:mcp__Gmail__send_message" e envie UMA mensagem: to ["ceccon.dm@gmail.com"], subject = conteúdo de work/out/newsletter_subject.txt, htmlBody = conteúdo exato de work/out/newsletter.html. Se o Gmail não existir na sessão ou o envio falhar, não trave e diga no aviso.

PASSO 8 — Aviso: poste no tópico uma linha curta para o Denny: "Agendão Curitiba de DD/MM: N eventos, X novos, Y resumos escritos" e, se houver, os sites que falharam na coleta (campo "failed" do primeiro item de state/runs.json), problemas no dashboard e, às sextas, se a newsletter saiu.
